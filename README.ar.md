## ⚡ البدء السريع (Above the Fold)

ثبّت وسجّل مهارة `tidyfactor-skill-architect` داخل بيئة التطوير الخاصة بك خلال ثوانٍ معدودة:

```bash
# الخيار أ: التثبيت عبر الأداة الرسمية لمنظومة تايدي فاكتور (موصى به)
npx @tidyfactor/cli add skill-architect

# الخيار ب: التثبيت عبر معيار مهارات الوكلاء المفتوح (skills.sh)
npx skills add tidyfactor/skill-architect

# الخيار ج: التشغيل المباشر الفوري بدون أي حزم عامة مثبتة
npx @tidyfactor/skill-architect@latest
```

## 🌟 نظرة عامة وفلسفة التصميم

يُعد **`tidyfactor-skill-architect`** النواة الحاكمة والمحرك المنهجي الذي يحدد المعايير الهندسية الصارمة لإنشاء، وتدقيق، وتوسيع، وحزم مهارات وكلاء الذكاء الاصطناعي في بيئات البرمجة الحديثة.

### المشكلة التي يعالجها

تعاني المهارات التقليدية لوكلاء الذكاء الاصطناعي من 4 اختلالات منهجية:
1. **استنزاف نافذة السياق (Context Pollution)**: حشو مئات التعليمات والبرومبتات في ملف واحد مما يستهلك آلاف التوكينات عند بدء كل جلسة، مما يضعف عمق الاستدلال.
2. **الهلوسة أثناء التنفيذ**: غياب المسارات الحتمية يجعل النموذج "يخمن" خطوات التنفيذ بدلاً من اتباع مسارات دقيقة ذات مخرجات واضحة.
3. **تشتت السلوك بين البيئات**: اختلاف استجابة النماذج بين Antigravity و Claude Code و Cursor نتيجة الانغلاق داخل منصة محددة.
4. **أخطاء الترويسة والصياغة**: كتابة نصوص YAML غير منضبطة أو غير محاطة بعلامات تنصيص، مما يكسر الإكمال التلقائي وقائمة الأوامر السريعة `/`.

### حل تايدي فاكتور

المهارة في منهجية تايدي فاكتور ليست مجرد مستند نصي، بل **مُوجّه توجيهي فائق السرعة (Deterministic Router)** يطبق مبدأ **الكشف التدريجي (Progressive Disclosure)**: تحميل الحد الأدنى الضروري من المعرفة التقنية في اللحظة المحددة لطلبها فقط.

### معمارية الكشف التدريجي (Progressive Disclosure)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                 طبقة الاستكشاف الأولي (Discovery Layer)                 │
│        ترويسة SKILL.md Frontmatter (الاسم + الوصف القصير ≤ 1024 حرفاً)  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (عند تطابق كلمات التحفيز)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                  طبقة التوجيه (Dispatcher Router)                       │
│        ملف SKILL.md (~350 توكين، مانعات التحفيز، نطاق صلاحية الأدوات)   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (تحديد نية المستخدم والأمر)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                 طبقة الأمر (Command Router Link)                         │
│              references/commands/<command>.md                           │
└──────────────────┬───────────────────────────────────┬──────────────────┘
                   │ (تحميل سير العمل)                 │ (حقن الذاكرة التشغيلية)
                   ▼                                   ▼
┌─────────────────────────────────────┐ ┌─────────────────────────────────┐
│      طبقة سير العمل                 │ │      طبقة الذاكرة التشغيلية     │
│     (Workflow Layer)                │ │      (Operational Memory)       │
│   خطوات التنفيذ المتسلسلة           │ │  قواعد تقنية، قوالب، جداول      │
│    + قائمة التحقق الإلزامية         │ │     (خالية من الحشو الإنشائي)   │
└─────────────────────────────────────┘ └─────────────────────────────────┘
```

## ⚡ الأوامر وسير العمليات التشغيلية

### جدول الأوامر التشغيلية

| الأمر | التصنيف | أمثلة على رسائل التحفيز | ما يتم تحميله | المخرج النهائي المحقق |
|---|---|---|---|---|
| **`init`** | إنشاء وبناء | `"ابنِ لي مهارة جديدة لـ X"`، `"أنشئ مهارة"` | `create-skill.md` + `spec.md` + `growth-rule.md` | هيكل مهارة متكامل ومطابق تماماً مع ترويسة YAML صالحة |
| **`audit`** | حوكمة وتدقيق | `"دقق هذه المهارة"`، `"افحص توافق القواعد"` | `audit-skill.md` + `spec.md` | بطاقة تقييم مطابقة القواعد الـ 15 وإصلاحات الكود الدقيقة |
| **`review`** | مراجعة دورية | `"راجع هذه المهارة"`، `"/review"` | `periodic-review.md` + `periodic-review-matrix.md` | بطاقة فحص مئوية للمحاور الـ 6 مع تقرير تصحيحي ميكانيكي |
| **`test`** | ضمان الجودة | `"اختبر المهارة"`، `"ولّد سيناريوهات فحص"` | `test-skill.md` + `spec.md` | إضافة $\ge 3$ سيناريوهات تقييم حتمية إلى `tests/scenarios.md` |
| **`grow`** | معمارية النظم | `"هل أضيف ملفاً جديداً؟"`، `"قيّم نمو المهارة"` | `growth-rule.md` | قرار حتمي ومبرر حسابياً (`SPLIT` أو `EXPAND` أو `REJECT`) |

---

### 1. `init` — بناء مهارة جديدة
- **الهدف**: إنشاء مهارة متوافقة تماماً مع معايير تايدي فاكتور من الصفر.
- **ما يتم تحميله**: `references/workflows/create-skill.md` + `references/memory/spec.md` + `references/memory/growth-rule.md` + `assets/skill-md-skeleton.md`.
- **المخرج النهائي**: هيكل مجلدات مكتمل، ملف `SKILL.md` توجيهي منضبط (~350 توكين)، أول سير عمل مختوم بـ `## Validation checklist`، وملفات التعريف الرسمية (`package.json`، `.tidyfactor`، `brand.yaml`).

### 2. `audit` — تدقيق مهارة قائمة وتصنيفها
- **الهدف**: قياس مدى مطابقة المهارة الحالية للقواعد الهيكلية الـ 15.
- **ما يتم تحميله**: `references/workflows/audit-skill.md` + `references/memory/spec.md`.
- **المخرج النهائي**: تقرير تدقيق رقمي (`النتيجة: X/15`)، قائمة بالمخالفات المرصودة، وفروقات برمجية (Diffs) دقيقة لتصحيح الملفات.

### 3. `review` — بروتوكول المراجعة الدوري سداسي المحاور
- **الهدف**: إجراء فحص صيانة دوري ربع سنوي أو تدقيق ما قبل الإصدار عبر الأبعاد الهندسية الستة.
- **ما يتم تحميله**: `references/workflows/periodic-review.md` + `references/memory/periodic-review-matrix.md`.
- **المخرج النهائي**: بطاقة تقييم موحدة من 100 نقطة، تنظيف الأصول اليتيمة والمكررة، وتحديث تواريخ الذاكرة القديمة.

### 4. `test` — توليد سيناريوهات الاختبار الحتمية
- **الهدف**: بناء سيناريوهات تقييم صندوق أسود لاختبار دقة التحفيز ومسارات التنفيذ ورفض الاستخدام الخاطئ.
- **ما يتم تحميله**: `references/workflows/test-skill.md` + `references/memory/spec.md`.
- **المخرج النهائي**: إضافة 3 سيناريوهات حتمية على الأقل إلى `tests/scenarios.md` (المسار الطبيعي، الحالة المعقدة، ومانع التحفيز).

### 5. `grow` — تقييم النمو والتوسع المعماري للمهارة
- **الهدف**: اتخاذ قرار هندسي موضوعي بشأن إضافة ملف جديد أو تقسيم سير العمل أو فصل مهارة مستقلة.
- **ما يتم تحميله**: `references/memory/growth-rule.md`.
- **المخرج النهائي**: قرار قطعي محدد كمياً بحجم الأسطر ($\ge 400$ سطر) وتنوع الفروع والمحفزات (`SPLIT` أو `EXPAND` أو `REJECT`).

## 🏛️ بروتوكول المراجعة الدوري سداسي المحاور (6-Axis Review)

أُضيف هذا البروتوكول في **الإصدار v2.7.0** ليوفر محرك صيانة دوري وموضوعي يمنع التدهور المعماري وتقادم المعرفة وتراكم الملفات المهملة بمرور الوقت.

### محاور التقييم الستة

```
   ┌────────────────────────────────────────────────────────┐
   │       محرك المراجعة الدوري سداسي المحاور العالمي        │
   └───────┬────────────┬────────────┬────────────┬─────────┘
           │            │            │            │
    ┌──────▼─────┐┌─────▼──────┐┌────▼───────┐┌───▼────────┐
    │  المحور 1  ││  المحور 2  ││  المحور 3  ││  المحور 4  │
    │   الأوامر  ││ سياقات العمل││   الذاكرة  ││   الأدوات  │
    └────────────┘└────────────┘└────────────┘└────────────┘
                        │                     │
                 ┌──────▼──────┐       ┌──────▼──────┐
                 │  المحور 5   │       │  المحور 6   │
                 │   الحوكمة   │       │ نظافة الأصول│
                 └─────────────┘       └─────────────┘
```

1. **المحور 1: انضباط الأوامر وسياق التوجيه (20 نقطة)**
   - تطابق جدول ملف `SKILL.md` التوجيهي بنسبة 100% مع مجلد `references/commands/`.
   - انضباط الموجه الأحادي، ومنع تشعب الأوامر غير الموثقة.
2. **المحور 2: سياقات العمل وقوائم التحقق الحاسمة (20 نقطة)**
   - سير عمل واحد = مخرج نهائي واحد ملموس.
   - ختام إلزامي لكل سير عمل بقائمة تحقق غير فارغة `## Validation checklist`.
3. **المحور 3: نقاء الذاكرة التشغيلية وأولوية YAML (15 نقطة)**
   - خلو ملفات الذاكرة من أي لغة تسويقية أو حشو دعائي.
   - تطبيق القاعدة 15 (أولوية YAML في `brand.yaml` والملخصات) لتوفير 35-50% من التوكنز.
   - سريان وسم الحداثة (`<!-- last-verified: YYYY-MM-DD -->` خلال $\le 180$ يوماً).
4. **المحور 4: حتمية الأدوات وغياب الانهيارات التشغيلية (15 نقطة)**
   - ضمان صفر انهيارات (Zero Runtime Crash) عبر أدوات Node/Python موثوقة في `tools/`.
   - فصل حدود خوادم MCP وتوفير بدائل محلية آمنة (Fail-Open).
5. **المحور 5: الحوكمة وتزامن SemVer ونبرة الصوت (15 نقطة)**
   - تزامن ذري تام للإصدارات عبر جميع ملفات البيانات الوصفية.
   - الالتزام الصارم بـ `CHANGELOG.md` وخلو المشروع من أي تسريبات للمفاتيح أو المسارات.
   - نبرة تقنية مباشرة وخالية من الترحيبات الآلية المصطنعة.
6. **المحور 6: نظافة الأصول وهيكلية المجلدات (15 نقطة)**
   - كشف وإزالة الصور والوسائط المكررة بحساب بصمة SHA-256.
   - حذف الملفات غير المستخدمة أو اليتيمة في `assets/`.
   - استخدام صيغة WebP المحسنة لخفة التحميل.

### مصفوفة التقييم المئوية ودرجات الاجتياز

| الدرجة | نطاق الدرجات | الحالة | الإجراء المطلوب |
|---|---|---|---|
| **الدرجة A** | **90 – 100** | ✅ **جاهز للإنتاج والنشر** | معتمد للإصدار المباشر والمزامنة عبر كافة الوكلاء. |
| **الدرجة B** | **75 – 89** | ⚠️ **تحذير بنواقص طفيفة** | يلزم تنفيذ إصلاحات النظافة أو تحديث التواريخ قبل الإصدار الرئيسي. |
| **الدرجة C** | **< 75** | ❌ **غير مجتاز لمعيار الجودة** | يمنع الإصدار. يجب تطبيق معادلات التصحيح الميكانيكية فوراً. |

## 📐 القواعد الهيكلية الخمس عشرة

تلتزم جميع المهارات في بيئة TidyFactor بـ **القواعد الهيكلية الـ 15** غير القابلة للتفاوض:

| # | القاعدة | الشرط الإلزامي | المشكلة التي تمنعها |
|---|---|---|---|
| **1** | **انضباط الموجه (Dispatcher Discipline)** | ملف `SKILL.md` هو موجه للأوامر فقط (~350 توكين) بدون أي خطوات تنفيذ داخلية. | استنزاف الذاكرة والتوكينات عند بدء الجلسة. |
| **2** | **سير عمل واحد = مخرج واحد** | كل سير عمل ينتج مخرجاً نهائياً واحداً وينتهي بـ `## Validation checklist`. | تشتت الوكيل في مهام متعددة وفشل التحقق. |
| **3** | **الذاكرة التشغيلية (Operational Memory)** | الذاكرة مخصصة للحقائق والقواعد والقوالب التقنية الصرفة بدون أي لغة تسويقية. | هلوسة الوكيل بنصوص دعائية داخل الكود الفعلي. |
| **4** | **منع المجلدات الفارغة (No Empty Structures)** | بنية مسطحة للملفات؛ لا يتم إنشاء مجلد لملف وحيد (`memory.md` بدلاً من `memory/`). | تعقيد التصفح وزيادة عمق المسارات غير المبرر. |
| **5** | **عزل الفلسفة (Philosophy Isolation)** | الفلسفة وتوجه العلامة يعزل في `memory/philosophy.md` ولا يقرأه الوكيل أثناء التنفيذ. | تشتيت الوكيل بفلسفة التصميم بدلاً من كود التنفيذ. |
| **6** | **النمو المشروط بالمحفزات (Trigger-Justified)** | لا تضاف ملفات أو مجلدات جديدة إلا بتحقق محفزات كمية صريحة (الحجم، الفروع، التنويعات). | التضخم المبكر والفوضى المعمارية في بنية المهارة. |
| **7** | **جودة الأدوات المحلية (Native Tooling)** | العمليات الحتمية تُعزل كأدوات في `tools/` فوق الأدوات الرسمية (`node` و `python`). | استبدالات الـ Regex غير المستقرة والسكربتات العشوائية. |
| **8** | **التطابق الصارم وإصدارات SemVer** | سلوك متطابق 100% عبر المنصات مع توثيق التغييرات حصراً في `CHANGELOG.md`. | التباين السلوكي بين الوكلاء والتغييرات غير الموثقة. |
| **9** | **توافق المنصات وصحة ترويسة YAML** | صحة مفسر `yaml.safe_load()`، وصف ≤ 1024 حرفاً، وإحاطة إجبارية `"..."` عند وجود علامات تنصيص أو نقطتين `:`. | اختفاء المهارة من قائمة أوامر `/` وفشل الـ Autocomplete. |
| **10** | **إعلان صلاحيات الأدوات (Tooling Scope)** | إعلان لغات البرمجة ونطاق تعديل الملفات والشبكة صراحة في `SKILL.md`. | الثغرات الأمنية وتعديل الملفات غير المصرح به. |
| **11** | **حداثة الذاكرة (Memory Freshness)** | وسم `<!-- last-verified: YYYY-MM-DD -->` إلزامي في كل ملف ذاكرة، وتحديثه خلال ≤ 180 يوماً. | استخدام دوال مهملة أو تعليمات برمجية غير متوافقة. |
| **12** | **حدود المهارة وخوادم MCP** | المعرفة وقواعد القرار داخل المهارة؛ والـ APIs الحية وقواعد البيانات تُفوض لخوادم MCP. | تضخم المهارات ومحاولة تنفيذ اتصالات حية غير مدعومة. |
| **13** | **توثيق متعدد اللغات من مستويين** | فصل صارم بين التوثيق التقني القياسي (`README.md`) و 7 لغات محلية مع شريط تبديل اللغات الثماني. | التردي اللغوي، ديون الترجمة، وتشتت الأسواق الثانوية. |
| **14** | **طبقة القرار السياقي (CDL v2.0)** | حساب $\text{Unknowns} = \text{Required} - (\text{Discovered} \cup \text{KIs})$، مسح بيئة العمل أولاً، استخدام النوافذ التفاعلية (`ask_question`) ودعم نمط المناظرة (Debate Mode). | استجواب المستخدم غير المبرر، الترحيبات الآلية، وانجراف الحالة. |
| **15** | **كفاءة التوكن والكثافة الدلالية (YAML Primacy)** | أولوية YAML للطبقة الإدراكية (`brand.yaml`، الملخصات، الذاكرة) لتوفير 35-50% من التوكنز مع حصر JSON للتشغيل الآلي. | استنزاف نافذة السياق، تشويش أقواس JSON، وأخطاء الفواصل الزائدة. |

## 🧠 طبقة القرار السياقي (CDL v2.0)

للمهام المعقدة التي تعتمد على خيارات معمارية مترابطة، تقنن المهارة **نمط التحكيم السياقي**:

### نمط التحكيم رباعي المراحل

1. **الاستكشاف السياقي النشط (Active Context Synthesis)**: مسح ملفات المشروع الحالية ومستودع المعرفة المتاح (KIs) لاستخلاص القرارات المحسومة مسبقاً وتجنب إعادة السؤال عنها.
2. **الملخص المسبق والتخزين المحلي (`brief`)**: حصر القرارات المتبقية وحفظها في `.tidyfactor/<skill>-brief.md` كمصدر حقيقة وحيد للتشغيل التلقائي الصامت لاحقاً.
3. **التحكيم التفاعلي الأحادي**:
   - **النمط التفاعلي الذكي (Mode A)**: منع طرح الأسئلة كنصوص في المحادثة؛ واستدعاء النوافذ التفاعلية المنبثقة للبيئة (`ask_question`) في جولة واحدة بحد أقصى 3 أسئلة.
   - **نمط المناظرة (Mode B / Debate Mode)**: تحليل ومناقشة الخيارات المعمارية الحرجة وتقديم التوصيات الهندسية المبررة قبل توليد الكود.
4. **محور التوافق مع القرارات (`D`)**: تدقيق الكود البرمجي الناتج للتأكد من مطابقته التامة للملخص المعتمد ضمن ختم التقييم المسبق (`/* Pre-emit critique: P5 H5 E5 S5 R5 V5 D5 */`).

## 🚀 دليل التثبيت والتشغيل المفصل

### خيارات أدوات سطر الأوامر (CLI)

اختر طريقة التثبيت المفضلة لديك:

#### الخيار أ: عبر أداة منظومة تايدي فاكتور (موصى به)
تثبيت المهارة مباشرة داخل مساحة العمل الحالية عبر الأداة الرسمية:
```bash
npx @tidyfactor/cli add skill-architect
```
*أو في حال كانت الأداة مثبتة عالمياً (`npm i -g @tidyfactor/cli`):*
```bash
tidyfactor add skill-architect
```

#### الخيار ب: عبر منظومة مهارات الوكلاء المفتوحة (skills.sh / Vercel Labs)
تثبيت المهارة عبر المعيار المشترك لكافة برامج التحرير الذكية (Cursor و Antigravity و Claude Code و Windsurf و Trae و Codex):
```bash
npx skills add tidyfactor/skill-architect
```

#### الخيار ج: التشغيل المباشر الفوري بدون تبعيات (NPM Direct)
تشغيل مثبت المهارة المستقل والمحدث تلقائياً:
```bash
npx @tidyfactor/skill-architect@latest
```

### التسجيل اليدوي للمهارة

يمكنك أيضاً نسخ مجلد المهارة يدوياً إلى مسار التخصيص الخاص بالوكيل:

```bash
# بيئة Google Antigravity و Gemini IDE (المسار العالمي للتخصيص)
cp -r tidyfactor-skill-architect ~/.gemini/config/skills/

# وكيل مساحة العمل المحلية (جذر المشروع)
cp -r tidyfactor-skill-architect .agents/skills/
```
