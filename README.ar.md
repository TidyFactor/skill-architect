## 🌟 نظرة عامة وفلسفة التصميم

يُعد **`tidyfactor-skill-architect`** النواة الحاكمة والمحرك المنهجي الذي يحدد المعايير الصارمة لإنشاء، وتدقيق، وتوسيع، وحزم مهارات وكلاء الذكاء الاصطناعي في بيئة التحرير والبرمجة.

### المشكلة التي يعالجها
تعاني المهارات التقليدية لوكلاء الذكاء الاصطناعي من المشاكل التالية:
1. **استنزاف نافذة السياق (Context Pollution)**: حشو مئات التعليمات والبرومبتات في ملف واحد مما يستهلك آلاف التوكينات عند بدء كل جلسة.
2. **الهلوسة أثناء التنفيذ**: غياب المسارات الحتمية يجعل النموذج "يخمن" خطوات التنفيذ بدلاً من اتباع مسار هندسي منضبط.
3. **تشتت السلوك بين البيئات**: اختلاف استجابة النماذج بين Antigravity و Claude Code و Cursor.
4. **أخطاء الترويسة والصياغة**: كتابة نصوص YAML غير منضبطة تتسبب في كسر الإكمال التلقائي وقائمة الأوامر السريعة `/`.

### حل تايدي فاكتور (TidyFactor Approach)
المهارة في منهجية تايدي فاكتور ليست مستنداً نصياً مليئاً بالحشو، بل **مُوجّه توجيهي فائق السرعة (Deterministic Router)** يقوم بتحميل الحد الأدنى اللازم من المعرفة التقنية في اللحظة المحددة لطلبها فقط.

```
┌─────────────────────────────────────────────────────────────┐
│                 طبقة الاستكشاف الأولي (Discovery)           │
│        ترويسة SKILL.md Frontmatter (الاسم + الوصف القصير)   │
└──────────────────────────────┬──────────────────────────────┘
                               │ (عند تطابق كلمات التحفيز)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                  طبقة التوجيه (Dispatcher Router)            │
│         ملف SKILL.md (~350 توكين، مانعات التحفيز، الصلاحيات)│
└──────────────────────────────┬──────────────────────────────┘
                               │ (تحديد نية المستخدم والأمر)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 طبقة الأمر (Command Router Link)             │
│              references/commands/<command>.md               │
└──────────────┬───────────────────────────────┬──────────────┘
               │ (تحميل سير العمل)             │ (حقن الذاكرة التشغيلية)
               ▼                               ▼
┌──────────────────────────────┐ ┌────────────────────────────┐
│      طبقة سير العمل          │ │      طبقة الذاكرة التشغيلية │
│     (Workflow Layer)         │ │      (Operational Memory)  │
│   خطوات التنفيذ المتسلسلة    │ │  قواعد تقنية، قوالب، جداول │
│    + قائمة التحقق الإلزامية   │ │     (خالية من الحشو الإنشائي) │
└──────────────────────────────┘ └────────────────────────────┘
```

## 📐 القواعد الهيكلية الخمس عشرة

تلتزم جميع المهارات في بيئة TidyFactor بـ **القواعد الهيكلية الـ 15** غير القابلة للتفاوض:

| # | القاعدة | الشرط الإلزامي | المشكلة التي تمنعها |
|---|---|---|---|
| **1** | **انضباط الموجه (Dispatcher Discipline)** | ملف `SKILL.md` هو موجه للأوامر فقط (~350 توكين) بدون أي خطوات تنفيذ داخلية. | استنزاف الذاكرة والتوكينات عند بدء الجلسة. |
| **2** | **سير عمل واحد = مخرج واحد** | كل سير عمل ينتج مخرجاً نهائياً واحداً وينتهي بـ `## Validation checklist`. | تشتت الوكيل في مهام متعددة وفشل التحقق. |
| **3** | **الذاكرة التشغيلية (Operational Memory)** | الذاكرة مخصصة للحقائق والقواعد والقوالب التقنية الصرفة بدون أي لغة تسويقية. | هلوسة الوكيل بنصوص دعائية داخل الكود الفعلي. |
| **4** | **منع المجلدات الفارغة (No Empty Structures)** | بنية مسطحة للملفات؛ لا يتم إنشاء مجلد لملف وحيد (`memory.md` بدلاً من `memory/`). | تعقيد التصفح وزيادة عمق المسارات غير المبرر. |
| **5** | **عزل الفلسفة (Philosophy Isolation)** | الفلسفة وتوجه العلامة يعزل في `memory/philosophy.md` ولا يقرأه الوكيل أثناء التنفيذ. | تشتيت الوكيل بفلسفة التصميم بدلاً من كود التنفيذ. |
| **6** | **النمو المشروط بالمحفزات (Trigger-Justified)** | لا تضاف ملفات أو مجلدات جديدة إلا بتحقق محفزات كمية صريحة (الحجم، الفروع، التنويعات). | التضخم المبكر والفوضى المعمارية في بنية المهارة. |
| **7** | **جودة الأدوات المحلية (Native Tooling)** | العمليات الحتمية تُعزل كأدوات في `tools/` فوق الأدوات الرسمية (`node` و `python`). | استبدالات الـ Regex غير المستقرة والسكربتات العشوائية. |
| **8** | **التطابق الصارم وإصدارات SemVer** | سلوك متطابق 100% عبر المنصات مع توثيق التغييرات حصراً في `CHANGELOG.md`. | التباين السلوكي بين الوكلاء والتغييرات غير الموثقة. |
| **9** | **توافق المنصات وصحة ترويسة YAML** | صحة مفسر `yaml.safe_load()`، وصف ≤ 1024 حرفاً، وإحاطة إجبارية `"..."` عند وجود علامات تنصيص أو نقطتين `:`. | اختفاء المهارة من قائمة أوامر `/` وفشل الـ Autocomplete. |
| **10** | **إعلان صلاحيات الأدوات (Tooling Scope)** | إعلان لغات البرمجة ونطاق تعديل الملفات والشبكة صراحة في `SKILL.md`. | الثغرات الأمنية وتعديل الملفات غير المصرح به. |
| **11** | **حداثة الذاكرة (Memory Freshness)** | وسم `<!-- last-verified: YYYY-MM-DD -->` إلزامي في كل ملف ذاكرة، وتحديثه خلال ≤ 180 يوماً. | استخدام دوال مهملة أو تعليمات برمجية غير متوافقة. |
| **12** | **حدود المهارة وخوادم MCP** | المعرفة وقواعد القرار داخل المهارة؛ والـ APIs الحية وقواعد البيانات تُفوض لخوادم MCP. | تضخم المهارات ومحاولة تنفيذ اتصالات حية غير مدعومة. |
| **13** | **توثيق متعدد اللغات من مستويين** | فصل صارم بين التوثيق التقني القياسي (`README.md`) و 7 لغات محلية مع شريط تبديل اللغات الثماني. | التردي اللغوي، ديون الترجمة، وتشتت الأسواق الثانوية. |
| **14** | **طبقة القرار السياقي (CDL)** | حساب $\text{Unknowns} = \text{Required} - (\text{Discovered} \cup \text{KIs})$، مسح بيئة العمل أولاً، وطرح خيارات تفاعلية بدون مقدمات آلية. | استجواب المستخدم غير المبرر، الترحيبات الآلية، وانجراف الحالة. |
| **15** | **كفاءة التوكن والكثافة الدلالية (YAML Primacy)** | أولوية YAML للطبقة الإدراكية (`brand.yaml`، الملخصات، الذاكرة) لتوفير 35-50% من التوكنز مع حصر JSON للتشغيل الآلي. | استنزاف نافذة السياق، تشويش أقواس JSON، وأخطاء الفواصل الزائدة. |

## ⚡ الأوامر وسير العمليات التشغيلية

توفر المهارة 4 أوامر تشغيلية أساسية:

### 1. `init` — بناء مهارة جديدة
- **الهدف**: إنشاء مهارة متوافقة تماماً مع معايير تايدي فاكتور من الصفر.
- **ما يتم تحميله**: `references/workflows/create-skill.md` + `references/memory/spec.md` + `references/memory/growth-rule.md` + `assets/skill-md-skeleton.md`
- **المخرج**: هيكل مجلد مهارة متكامل وجاهز مع ملف `SKILL.md` خفيف وفعال وترويسة YAML قياسية.

### 2. `audit` — فحص وتدقيق مهارة موجودة
- **الهدف**: فحص مهارة حالية وتحديد درجة مطابقتها للقواعد الهيكلية الـ 15.
- **ما يتم تحميله**: `references/workflows/audit-skill.md` + `references/memory/spec.md`
- **المخرج**: تقرير تدقيق رقمي (`النتيجة: X/15`) مع جدول تفصيلي بالمخالفات وخطوات الإصلاح الفوري.

### 3. `test` — توليد سيناريوهات الاختبار
- **الهدف**: إنشاء سيناريوهات اختبار تغطي المسار القياسي والحالات الحدية ومانعات التحفيز.
- **ما يتم تحميله**: `references/workflows/test-skill.md` + `references/memory/spec.md`
- **المخرج**: ملف `tests/scenarios.md` يحتوي على 3 سيناريوهات اختبار حقيقية على الأقل.

### 4. `grow` — تقييم نمو وتوسع هيكل المهارة
- **الهدف**: تقييم ما إذا كان الملف أو المجلد الجديد مبرراً هندسياً أم يجب دمجه.
- **ما يتم تحميله**: `references/memory/growth-rule.md`
- **المخرج**: قرار حتمي (`SPLIT` فصل، `EXPAND` توسيع، أو `REJECT` رفض التوسع غير المبرر).

## 🧠 طبقة القرار السياقي (CDL)

بالنسبة للمهارات المتقدمة التي تعتمد على قرارات معمارية متعددة الخيارات (مثل `tidyfactor-styler` و `tidyfactor-next`)، تقنن هذه المهارة نمط **CDL**:

1. **بروتوكول التحكيم الخفيف (`memory/decision-points.md`)**: محفزات واضحة وشروط تخطي تشير للكتالوجات الحالية بدون تكرار.
2. **المقابلة التأسيسية والكاش التلقائي (`brief` / `.tidyfactor/<skill>-brief.md`)**: أخذ تفضيلات المشروع مرة واحدة وتخزينها، لتشغيل الأوامر التالية بدون أسئلة متكررة.
3. **التجميع في جولة واحدة وخيارات افتراضية آمنة**: تجميع الأسئلة في دفعة واحدة (بحد أقصى 3 أسئلة) مع اعتماد الافتراضات الآمنة للباقي.
4. **محور محاذاة القرار (Axis 7: Decision Alignment)**: التأكد التلقائي أثناء النقد الذاتي من مطابقة الكود المولد مع القرارات المعتمدة.

## 🛠️ حزمة التحقق والتأكد الحتمي من النزاهة

تحتوي المهارة على أداة فحص رقمية متطورة تضمن سلامة البناء:

```bash
# تشغيل أداة التحقق الشاملة ذات الـ 11 نقطة فحص
python tools/validate_skill.py
```

### مصفوفة الفحوصات التلقائية (11 بوابة تحقق):
- `[1]` **مزامنة الإصدارات (SemVer)**: تطابق الإصدار في `package.json` و `.tidyfactor` و `brand.json` و `CHANGELOG.md`.
- `[2]` **فحص الترخيص**: وجود ملف الترخيص المعتمد Apache-2.0.
- `[3]` **سلامة الروابط والملفات**: التأكد من وجود كافة الملفات المشار إليها في `SKILL.md` على القرص.
- `[4]` **قوائم التحقق في سير العمل**: احتواء كل ملف workflow على `## Validation checklist`.
- `[5]` **حماية الخصوصية ومنع التسريب**: عدم وجود مسارات مطلقة خاصة بجهاز المطور داخل الملفات.
- `[6]` **ميزانية التوكينات**: التأكد من أن `SKILL.md` في حدود ~350 توكين (حد أقصى 500).
- `[7]` **حداثة الذاكرة**: التحقق من وسم `last-verified` ألا يتجاوز 180 يوماً.
- `[8]` **الفحص الصارم لترويسة الـ YAML**: استخدام `yaml.safe_load()` لضمان خلو الترويسة من أي أخطاء وكون الوصف ≤ 1024 حرفاً ومحاطاً بعلامات تنصيص سليمة.
- `[9]` **إعلان صلاحيات الأدوات**: التحقق من إعلان نطاق العمليات في حال وجود مجلد `tools/`.
- `[10]` **سيناريوهات الاختبار**: التأكد من وجود $\ge 3$ سيناريوهات اختبار في `tests/scenarios.md`.
- `[11]` **توثيق حدود MCP**: توثيق الحدود المعمارية في حال الاعتماد على خوادم خارجية.

## 🔄 المزامنة الذرية والتوزيع متعدد البيئات

عند استخدام أمر البناء `node tools/build-skill.js`، يتم توليد حزم التوزيع ومزامنة التحديثات تلقائياً عبر المسارات الخمسة:

```
Skills-LAB/tidyfactor-skill-architect/ (المصدر الأساسي SSOT)
  ├── 📦 dist/tidyfactor-skill-architect.skill
  ├── 📦 dist/tidyfactor-skill-architect-vX.Y.Z.skill
  ├── 🔁 .agents/skills/tidyfactor-skill-architect/ (بيئة الوكيل المحلي)
  ├── 🔁 ~/.gemini/config/skills/tidyfactor-skill-architect/ (بيئة Gemini / Antigravity العالمية)
  └── 🔁 /mnt/skills/user/tidyfactor-skill-architect/ (بيئة Claude Code / Unix)
```

## 📦 التثبيت وطرق الاستخدام

### 1. عبر مدير الحزم NPM / NPX
```bash
# الإضافة المباشرة إلى بيئة عمل الوكيل النشطة
npx @tidyfactor/cli-skill-architect

# أو التثبيت العام على مستوى النظام
npm install -g @tidyfactor/skill-architect
```

### 2. التسجيل اليدوي في بيئات الذكاء الاصطناعي
انسخ مجلد المهارة إلى المسار المخصص لوكيلك:
```bash
# Google Antigravity & Gemini IDE
cp -r tidyfactor-skill-architect ~/.gemini/config/skills/

# Local Project Agent Wrapper (.agents)
cp -r tidyfactor-skill-architect .agents/skills/
```
